# Deploying MockHRIS to AWS

This guide deploys MockHRIS to AWS with the Terraform module in [`deploy/terraform`](../deploy/terraform). It is a demonstration-grade deployment: small, cheap and easy to tear down, but built with sensible security defaults.

## Architecture

```
                 allowed_cidrs only
   You / MCP  ------------------------+
   clients                            v
                          +-----------------------+
                          |  Application Load     |  :80  (or :443 + redirect
                          |  Balancer (public)    |        when certificate_arn set)
                          +-----------+-----------+
                                      | :8000, from ALB security group only
        VPC (2 AZs)                   v
   +----------------------------------------------------------+
   |  ECS Fargate service "mockhris" (1+ tasks, awsvpc)        |
   |  image: ghcr.io/dddaaammmooo/scim-mock-hris               |
   |  task role: DynamoDB item access on this app's tables     |
   +-----+-------------------------+-------------------+------+
         | DynamoDB gateway        | Secrets Manager   | CloudWatch Logs
         | endpoint (free)         | (API key, tokens) | /ecs/mockhris
         v                         v                   v
   +-------------+          injected as env at start   log group
   | DynamoDB    |          (MOCKHRIS_API_KEY,
   | 7 tables,   |           INTEGRATION_TOKEN_<ID>)
   | on-demand,  |
   | PITR + SSE  |
   +-------------+
```

Task placement is a cost choice (variable `use_nat_gateway`):

| Mode | Tasks run in | Egress | Extra cost | Trade-off |
|---|---|---|---|---|
| Default (`false`) | public subnets, with a public IP | internet gateway | none | Tasks have a public IP, but their security group accepts traffic only from the ALB. Simple and cheapest. |
| `true` | private subnets | one NAT gateway | about 32 USD/month plus data | No public IP on tasks. A single NAT is a single-AZ dependency, which is fine for a demo. |

## Prerequisites

- An AWS account and credentials in your shell (`aws sts get-caller-identity` works) with permission to create VPC, ECS, ELB, IAM, DynamoDB, Secrets Manager and CloudWatch resources.
- [Terraform](https://developer.hashicorp.com/terraform/install) 1.6 or newer.
- AWS CLI v2 (to read the API key).
- The container image must exist in GitHub Container Registry as a public package (`ghcr.io/dddaaammmooo/scim-mock-hris`). No pull credentials are needed.
- Optional: an ACM certificate (same region) and a DNS name you control for HTTPS.

## Deploy

```bash
cd deploy/terraform
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars`. The only required value is `allowed_cidrs`, the IP ranges allowed to reach the load balancer (find your IP with `curl https://checkip.amazonaws.com`):

```hcl
allowed_cidrs = ["203.0.113.10/32"]
```

Then:

```bash
terraform init
terraform plan -out tfplan
terraform apply tfplan
```

Apply takes a few minutes. Useful outputs:

```bash
terraform output url                   # http(s)://<alb-dns>
terraform output get_api_key_command   # AWS CLI command that prints the API key
terraform output table_names
```

### Optional settings

| Goal | Variables |
|---|---|
| HTTPS | `certificate_arn` (HTTP then redirects to HTTPS). With a custom host name also set `domain_name` and create a CNAME or alias record to `terraform output alb_dns_name`. |
| Pin the image | `image = "ghcr.io/dddaaammmooo/scim-mock-hris:<tag>"` |
| Private tasks | `use_nat_gateway = true` |
| Existing network | `create_vpc = false`, `vpc_id`, `alb_subnet_ids`, `task_subnet_ids`, `assign_public_ip` |
| Provision into scim-target | `integration_tokens = { HRIS_TARGET = "<token>" }` (see below) |
| Empty database | `auto_seed = false` |
| Bigger or more tasks | `cpu`, `memory`, `desired_count` |

## First login and use

1. Read the API key (the secret is generated by Terraform unless you set `api_key`):

   ```bash
   aws secretsmanager get-secret-value --region us-east-1 \
     --secret-id "$(terraform output -raw api_key_secret_arn)" \
     --query SecretString --output text
   ```

2. Open `terraform output -raw url` in a browser. The API is protected by the key, so enter it in the UI when prompted, or pass it to the API:

   ```bash
   curl -H "X-API-Key: $KEY" "$(terraform output -raw url)/api/users" | head
   ```

   `/api/health` is always open (it is the load balancer health check).

3. The fictitious company is seeded on first start (`auto_seed = true`). Tables live in DynamoDB, so data survives task restarts and redeploys.

4. MCP clients connect to `terraform output -raw mcp_url` and send the key as `X-API-Key` or `Authorization: Bearer`. `MCP_ALLOWED_HOSTS` is set automatically to the ALB DNS name and `domain_name`.

If `/mcp` rejects requests with an invalid Host header error (typically HTTP 421), the Host header you used is not in `MCP_ALLOWED_HOSTS`; add it with `extra_mcp_allowed_hosts`.

### Pointing MockHRIS at a deployed scim-target

If you also deployed [scim-target](https://github.com/dddaaammmooo/scim-target) with its Terraform module:

1. In the scim-target stack, run `terraform output scim_base_url` and `terraform output get_scim_token_command`.
2. In MockHRIS, create or edit an integration and set:
   - SCIM base URL: `http://<scim-target-alb>/t/hris/scim/v2` (the `scim_base_url` output)
   - Token: the scim-target SCIM token.
3. Prefer not to store the token through the UI: set `integration_tokens = { <INTEGRATION_ID> = "<token>" }` in this stack. It is stored in Secrets Manager and injected as `INTEGRATION_TOKEN_<ID>` (upper-case, `-` replaced by `_`).
4. scim-target restricts access by IP. Add the MockHRIS task egress IP to scim-target's `allowed_cidrs`. With the default placement the egress IP is the task public IP, which changes on every deployment, so for a stable address use `use_nat_gateway = true` (the NAT Elastic IP is stable; see the VPC console) or run both stacks with a shared existing VPC and a private ALB.

## Cost notes

Approximate us-east-1 on-demand prices; check the AWS pricing pages.

| Item | Approx. monthly |
|---|---|
| Fargate, 0.25 vCPU / 0.5 GiB, 1 task running 24x7 | about 9 USD |
| Application Load Balancer | about 17 USD plus tiny LCU usage |
| Public IPv4 addresses (ALB uses 2, the task 1 in default mode) | about 0.005 USD per address-hour each |
| NAT gateway (only with `use_nat_gateway`) | about 32 USD plus 0.045 USD/GB |
| DynamoDB on-demand, 7 tables, light use | well under 1 USD (PITR adds a per-GB charge) |
| DynamoDB gateway endpoint | free |
| CloudWatch Logs | per GB ingested; retention defaults to 14 days |
| Secrets Manager | about 0.40 USD per secret |

The ALB and Fargate dominate. To pause spending without destroying data, set `desired_count = 0` (the ALB still bills); to stop everything, destroy.

## Security notes

- Ingress is limited to `allowed_cidrs`; there is no default. Using `0.0.0.0/0` exposes the app to the internet, so pair it with the API key and HTTPS.
- `require_api_key` defaults to `true`. The key is generated with `random_password`, stored in Secrets Manager and injected into the task by ECS. It also lives in Terraform state, so protect the state (use an encrypted S3 backend with restricted access; an example block is in the module README).
- Without `certificate_arn` traffic is plain HTTP, including the API key. Use HTTPS for anything beyond a quick test from a trusted network.
- The task role can only call `ListTables` plus item-level actions on the seven tables. The execution role can only read the secrets this stack creates.
- Tables use on-demand billing, server-side encryption and point-in-time recovery.
- The data is fictitious. Do not load real employee data into MockHRIS.

## Operations

```bash
# Logs
aws logs tail "$(terraform output -raw log_group)" --follow

# Roll out a new image tag
terraform apply -var 'image=ghcr.io/dddaaammmooo/scim-mock-hris:<tag>'
```

Deployments use the ECS circuit breaker: if new tasks fail their health check, ECS rolls back to the previous task definition automatically.

## Teardown

```bash
terraform destroy
```

This deletes the tables and all data. If you set `dynamodb_deletion_protection = true`, first set it to `false` and run `terraform apply`. If you set `alb_deletion_protection = true`, do the same for it. Secrets Manager keeps deleted secrets for `secret_recovery_window_days` (default 7), and a new stack with the same `name` cannot reuse the secret names during that window. Set `secret_recovery_window_days = 0` for throwaway stacks.
